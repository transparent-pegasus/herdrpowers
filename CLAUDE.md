# Claude Code Guide

This repository IS the herdrpowers plugin: the payload lives directly at the repo root in `skills/` and `commands/`, discovered by the Claude Code, Codex, and Cursor plugin conventions (manifests in `.claude-plugin/`, `.codex-plugin/`, `.cursor-plugin/`, plus the Codex marketplace file at `.agents/plugins/marketplace.json`), and by OpenCode through `package.json`, whose `main` is `.opencode-plugin/index.mjs`: that plugin registers `skills/` and every `commands/*.md` (as `/herdrpowers:<name>`) through a v1 config hook or v2 setup/transforms. The default export carries `id`, `setup`, and the v1 `server` adapter; the named `Herdrpowers` function remains available for direct imports. It uses only Node built-ins and must remain dependency-free unless the scanner lockfile disposition is updated. `package.json` carries the pack version alongside the four manifests, and must not declare `"type": "module"` — that would turn the payload's CommonJS scripts (`skills/writing-skills/render-graphs.js`) into broken ES modules.

When editing pack behavior, edit `skills/` or `commands/` directly. `docs/` holds the human-facing framework docs. This file and `AGENTS.md` are maintainer instructions only — they are not part of the payload.

## Pack Invariants

- **Dispatch follows the canonical profiles contract.** Read `skills/orchestration/references/profiles.md` before routing. Separate delegated targets use reset-backed Herdr panes through `using-herdr-sibling-panes`. With a selected profile, self-target `delegate` requires a fresh in-process subagent for work and reviews, including solo coder/empty reviewers; other owner-session modes permit inline work/self-review and optional subagents at the active owner's judgment. Missing mandatory subagent capability is inability, never inline delegation or a passed gate. Without a profile, preserve legacy routing and fresh-subagent orchestrator-mode reviews. Workers never re-delegate. Skill-authorship testing still uses fresh API/reset-pane samples under `writing-skills`, never in-session sampling.
- **Roles and task names, not tool names.** Skills name roles and delegation tasks. Resolve repo `.herdrpowers/config.yaml` over shipped `skills/orchestration/roles.yaml`, then overlay only composition keys present in the selected profile. Preserve custom roles, planning-design/generalist bindings, assignments, modes, and gates. Bare `orchestrator` is a dynamic active-owner alias. `roles.yaml` is the default layer, never a consumer customization point. This checkout is the upstream plugin; do not initialize it as a consumer merely to edit payload behavior.
- **The YAML is the source of truth for defaults; prose points at it.** No skill, command, or doc restates a shipped `role`/`mode` value — they name what a task covers and say "read the resolved assignment". A `| Default |` column in a payload table is a bug: it goes stale silently and gives agents a second, wrong answer. Adding a role, a delegation task, or a `delegation:` key means updating `roles.yaml` plus the tables in `skills/orchestration/SKILL.md`, `commands/init.md`, and `docs/roles.md` — the tables, not defaults inside them.
- **Delegation never crosses the orchestrator's tab unless the repo says so.** `delegation.pane_scope` defaults to `tab`; an out-of-scope pane is not a candidate, not a fallback target, and not counted toward an agent type's availability. A payload file that selects panes without filtering on `tab_id` is a bug. Scope is never widened mid-run — that is a configuration change, and configuration is read-only inside a run.
- **Targets and list slots are explicit.** New role/profile targets use nested `{kind: {model: ..., effort: ...}}`; effort requires model. Legacy non-fallback `kind@model` is migration input only. Separate list slots need distinct kinds or distinct pinned models (case-insensitive, neither containing the other); effort alone adds no independence. Model/effort must match live footer evidence before keys and after reset; unknown evidence fails closed. Never switch an existing agent's settings. Fallback keys/substitutes retain exact effort-free strings; a matched empty list is authoritative and primary effort is discarded. Preserve `Calude` and the unequal Muse spellings.
- **Review independence and self-review are reported precisely.** Separate delegated reviews start fresh sessions; the same physical pane may review after reset, with no prefer-different-type heuristic. Profile owner-session self-review is the scoped exception; self-target `delegate` still needs a fresh subagent. Disabled gates remain disabled, while explicit empty profile reviewers select the owner. Legacy empty role lists retain disabling semantics unless overridden by a present profile key. Delegated test authors get requirements alone at BASE without implementation; `implementer` owns its own RED-GREEN evidence. Report test writer/transport, changed assignments, disabled gates, and actual review independence. Profile self-target fix loops retain their mode; separate targets and no-profile routing retain escalation and the five-round cap.
- **Owner handoff and lifecycle are guarded separately.** A selected-owner mismatch always asks unused versus relay before handoff or startup. Explicit owner handoff transfers authority and frozen settings; it is distinct from worker delegation. Top-level `allow_agent_lifecycle` is a strict boolean, false by default, and it is enforced in code: every start and end goes through `skills/using-herdr-sibling-panes/scripts/agent-lifecycle.sh`, which exits 6 unless the resolved value is the literal `true`. A payload file that starts or ends an agent any other way is a bug. False forbids start/exit/restart, including recovery/fallback. True starts a resolved target that has no live in-scope match — the primary before its substitutes — in an available shell pane inside scope and the task's repository, verifies the live footer, and ends only ledger-recorded idle agents with no pending work, using the exit keys observed for that CLI in `references/agent-lifecycle.md`; a kind without observed keys is left running and reported. It does not permit topology changes, interrupting working agents, answering startup dialogs, or widening scope. The permission is configuration-only, while a profile may also be named in the task for that run. Never invent a stop command.
- **`<KEY>` placeholders are intentional.** They resolve at runtime from each target repo's `Herdrpowers Configuration` section (written by the `init` workflow). When adding a new placeholder, add it to the key table in `commands/init.md`.
- Keep skill cross-references as bare skill names (`writing-plans`, not `herdrpowers:writing-plans`); Claude Code namespaces them automatically at install time (`herdrpowers:<name>`).

## Maintenance

- Every upstream refresh from `obra/superpowers` MUST add a self-contained entry under `changelogs/` (YAML frontmatter with `upstream_repo`, `upstream_version`, `upstream_sha`, `previous_upstream_sha`, `ours_from_sha`, `ours_to_sha`; summary; upstream coverage; reconciliation decisions; full unified diff in a ```diff block) and update `changelogs/UPSTREAM_SHA`. Structural pack-native changes get a summary entry (no diff required). Reconcile upstream dispatch with the canonical profile/no-profile routing contract before landing a refresh.
- Keep every `skills/*/SKILL.md` under 20,000 bytes so its required steps survive skill reattachment after compaction. Run `bash tests/skill-size/test-skill-size.sh` after edits. Move supporting detail into `references/` with an explicit read instruction at each step that needs it; preserve the routing and independence rules when moving text.
- Validate after edits: `claude plugin validate .claude-plugin/plugin.json` and `claude plugin validate .` (marketplace), plus `rg -n 'subagent_type|test-engineer|code-reviewer|Agent tool|superpowers-extended' skills commands docs README.md` to catch resurrected pre-merge references, `bash tests/pane-model/run.sh` for the footer model-line reader, `bash tests/pane-model/effort.sh` and `bash tests/pane-model/muse.sh` for effort and Muse footers, `node --test tests/pane-model/pane.test.mjs tests/composer-submit/submit.test.mjs tests/orchestration-profiles/profiles.test.mjs tests/agent-lifecycle/lifecycle.test.mjs` for the helpers, the shipped profile assets, and the lifecycle gate, `node --test tests/opencode/plugin.test.mjs` for both OpenCode APIs, and `node --input-type=module -e 'import { Herdrpowers } from "./.opencode-plugin/index.mjs"; const c = {}; await (await Herdrpowers()).config(c); console.log(c.skills.paths, Object.keys(c.command))'` for the OpenCode entry point (expect the `skills/` path and one `herdrpowers:<name>` per workflow). Expect no rg hits outside `changelogs/`; `docs/roles.md` and the payload's own prohibitions name these terms only to forbid them. `README.md` states the pack's lineage against `obra/superpowers` alone — the intermediate `superpowers-extended` fork belongs in `NOTICE`, which is the legal attribution chain and must keep it.
