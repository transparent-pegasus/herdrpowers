# v1.9.0 — Two undocumented sibling-pane failure modes

## Summary

Adopts `herdr-orchestration` commit `53c670e` ("docs: record two undocumented sibling-pane failure modes") into `skills/using-herdr-sibling-panes/SKILL.md`. Documentation only — no helper script, routing, or `roles.yaml` change.

**Submitted but idle.** A brief beyond a few hundred characters can land in the composer as `[Pasted Content 1024 chars] #2 #3` and never submit, while `composer-submit.sh` still exits `0` — the pane flickers to `working` during the paste and passes the `started()` `working|blocked` check, so the orchestrator waits on a delegation that never began. Observed 2026-08-22 at roughly 3000 characters. The guidance is to put a long brief in a file (under `<REPORT_DIRECTORY>` or the worktree scratch directory) and submit a one-line pointer to it, and to treat exit `0` as "submission attempted", never as evidence of completion — confirm movement with `git status` in the worktree or the named report file.

**Refused on policy.** A brief that reads as an attack recipe is refused with a cybersecurity policy message even when the work hardens the repository's own code. Observed 2026-08-22 on a codex pane. The guidance is to write the defender's invariant instead of the attacker's viewpoint, to inspect the worktree before discarding anything (the refusal can land *after* the work is done — observed with 374 lines of tests already written and only the commit-and-report step refused), and to reword and re-delegate to the same pane rather than treating the refusal as exhaustion and falling back.

Both states get a row in the "Failure handling" table. Placement follows the source commit: the two paragraphs sit at the end of the task contract, immediately before the worked `composer-submit.sh` example. `<REPORT_DIRECTORY>` replaces the source's prose reference to the task's report directory, matching this pack's placeholder convention.

## Not adopted

`herdr-orchestration` commit `6f37056` renames `plan-double-review` to `plan-review` and adds an `integration-review` gate. That is review-gate routing, not delegation transport, and this pack's gate set (`task-review`, `fix-round-re-review`, `final-branch-review`) differs from the sibling's — it needs its own reconciliation pass across `roles.yaml`, `skills/orchestration/SKILL.md`, `commands/init.md`, `commands/plan.md`, `commands/full_cycle.md`, and `docs/roles.md`.
