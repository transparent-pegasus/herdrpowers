## Reconciliation decisions

- **Rulings adopted, with one pack-native boundary.** A ruling resolves what the
  spec and the plan leave open. It does **not** raise the five-round cap,
  re-enable a gate the repository disabled, disable one it enabled, widen
  `delegation.pane_scope`, or touch `.herdrpowers/config.yaml`. That paragraph is
  ours, not upstream's, and it exists because this fork treats configuration as
  the user's declaration resolved once at start. Without it, "a cap you would
  have asked to exceed — decide it" (upstream's phrasing) reads as authority to
  rewrite the run's terms, contradicting the existing rationalization row about
  turning gates off mid-loop. Our phrasing is "a fix round that ended at the
  cap": the ruling settles what happens *at* the cap, never whether there is one.

- **Workflow-level human gates are untouched.** "Rulings, not stalls" governs the
  task loop only. Plan approval, the `documentation-impact-review` sweep, and the
  integration decision in `finishing-a-development-branch` remain the human's,
  and the four stop-classes (irreversible/destructive operation,
  security-sensitive action, side effect outside the worktree, a plan so broken
  every path forward is a guess) are unchanged from upstream.

- **A dangling graph node was fixed, not copied.** Upstream's rewrite left
  `"Rule and continue; stop only if every path forward is a guess"` with no
  outgoing edge — terminal in the rendered graph, while the prose says continue.
  Added the edge to `"Append completion to ledger, mark todo complete"`.

- **Upstream's duplicated preflight sentence was collapsed.** Its new paragraph
  says "Rule on everything you find … record each ruling" and then repeats "Rule
  on each conflict it surfaces … record the ruling beside its row". Kept one.

- **Batching was extended to say what happens to per-task bookkeeping.** Upstream
  stops at "review its diff as one unit". This fork carries a per-task ledger, a
  per-task review package, and (under `test-authoring: {mode: delegate}`) a
  second pane on the same brief — so the adopted text names all three: one review
  package, one review, one completion line naming every task in the batch, and
  the test author works from the same batched brief.

- **Bounded waits went to the transport skill, not the loop skill.**
  `using-herdr-sibling-panes` owns wait mechanics for every delegating skill;
  duplicating them in `pane-driven-development` would give agents two sources.
  `pane-driven-development` gets a four-line pointer instead.

- **Bounded stretches are paired with a report-file check, because this fork's
  wait interface has a gap upstream's does not.** `herdr wait output` only scans
  output emitted after it starts, so splitting one 30-minute wait into five-minute
  stretches drops any marker that lands between them. The adopted paragraph makes
  the between-stretch check mandatory and says why — bounded stretches without it
  would have introduced a marker-miss bug that the single long wait does not have.

- **"You Do Not Dispatch Subagents" became "You Do Not Delegate Onward"** in the
  three reviewer contracts, which had the clause only in their one-line submitted
  instruction, not in the contract body. The implementer contract already banned
  re-delegation, so upstream's reviewer-specific rationale ("that review is
  already scheduled") was folded into the existing sentence rather than added as a
  second section. `test-author-brief.md` already carries the ban and needed no
  change.

- **The pack's structural prohibition is unchanged and still stronger.** Upstream
  is converging by prompt on what `CLAUDE.md`'s first invariant already forbids
  outright: no in-process subagents anywhere in the payload. Nothing adopted here
  reintroduces subagent dispatch.
