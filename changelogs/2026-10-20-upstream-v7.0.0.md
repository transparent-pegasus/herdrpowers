# Upstream Refresh — v7.0.0: Brainstorming Rebuilt Around Intent, Builder Check on the plan-review Gate

Adopts the payload-relevant parts of upstream's v7.0.0 release. Upstream
rebuilt `brainstorming` from scratch: a private "what do I actually know?"
check, a first message that offers to skip the questions and asks one open
question, playback in 200-300-word chunks, finding out which
how-it-gets-made choices the user wants to own, and sizing the work only
after intent is clear — a quick, clear task, a small change agreed in chat,
or a project with a written design. A written design gets a **builder
check**: a fresh reader plays the person who will build it and lists what
they would still need to ask. The release also inserts visual-companion
content literally, keeps a repo's own workspace `.gitignore`, resolves the
workspace root physically for Git Bash, and stops a debugging example from
printing the secret it checks for.

Bumps the pack to **1.17.0** across the four manifests and `package.json`:
brainstorming changes how every piece of work starts — new behavior, not a
fix.

## Reconciliation decisions

- **The builder check is the `plan-review` gate.** Upstream dispatches a
  fresh general-purpose subagent; the payload allows an in-process subagent
  only for a review task resolved to `mode: orchestrator`. Two alternatives
  were set aside. A new review task (`builder-check`) would add a key to
  `roles.yaml`, the three tables, and the init template — the 2026-10-09
  entry held that adding a delegation task is a decision a refresh should
  not make alone. An inline self-read would drop the fresh reader the check
  exists for. `plan-review` already describes itself as independent review
  of "a plan or design before approval", `orchestration`'s "Plan/design
  review" section owns it, and the Reviewer role covers designs. Mapping an
  upstream dispatch onto an existing gate follows the 2026-10-09 precedent
  (`executing-plans`' final reviewer → `final-branch-review`). Consequences,
  all stated where they apply: in `/plan` and `/full_cycle` the gate now
  runs at two points; `enabled: false` removes both; a list role multiplies
  both (init's arithmetic rule says so); `/strict_full_cycle` forces both.
  The `plan-review` rows in `orchestration`, `docs/roles.md`, and
  `commands/init.md` and its `roles.yaml` description name the builder
  check. No `role`, `mode`, or `enabled` value changed.

- **Several readers, one round.** A list role runs the check once per
  entry. Brainstorming merges the readers' questions (the same question from
  two readers is one) before sorting them into upstream's three piles, so
  the user still gets a single round.

- **Degrading follows `orchestration`.** Upstream: without a subagent tool,
  read the document as the builder yourself. Here: under `mode: delegate`
  with no usable pane (`HERDR_ENV` unset, or no in-scope pane of the role or
  its fallbacks) the orchestrator reads it as the builder and says the check
  was not independent — as the plan review already does. Under
  `mode: orchestrator` a subagent that cannot be spawned means the check
  degraded, with no self-read, per "Never inline". A disabled gate skips the
  check and is never replaced by the orchestrator's own read.

- **The prompt became a pane brief.** `builder-check-prompt.md` →
  `builder-check-brief.md`, as `code-reviewer.md` became `review-brief.md`:
  upstream's prompt verbatim as the contract, plus the transport — a
  one-line instruction pointing at the contract file, the absolute
  repository path, the read-only clause, a report file under
  `<REPORT_DIRECTORY>`, a split completion marker, the git-cleaning
  prohibition, and no onward delegation.

- **The design stays uncommitted at `<DESIGN_DOC_PATH_PATTERN>`.** Upstream
  keeps `docs/superpowers/specs/…`, committed. The pack's placeholder and
  Git Management note stay; upstream's "otherwise, ask" for non-software
  work is adopted.

- **One routing nod, after the Size table.** v6.3.0 put "a task the
  orchestration skill routed stays routed" in the bounded checklist, which
  upstream removed. One sentence after the Size table now covers both "do
  it" and "build it through the normal workflow".

- **Codegraph moved into recon.** The pack's codegraph-first discovery used
  to open the architectural checklist. Upstream now *offers* to look; the
  codegraph sentence sits in "Offer recon" and applies once the user lets
  you into a codebase.

- **Phrasing.** "Your human partner" became "the user", as brainstorming
  has said since v6.3.0; `superpowers:writing-plans` became `writing-plans`.
  The description is adopted verbatim, as the pack has tracked upstream's.
  Adopted text keeps upstream's line wrapping, as `executing-plans` and
  `writing-plans` did on 2026-10-09, so the next refresh diffs line for
  line; the pack-native paragraphs stay single-line.

- **Dropped with upstream:** the spike / bounded / architectural paths,
  their checklists and flowchart, the inline spec self-review, "Design for
  isolation and clarity", "Working in existing codebases", and the
  elements-of-style pointer. The rebuild design lists designing
  architecture the user did not ask to decide as a non-goal.

- **Workflows say the size and never downgrade.** `/plan`, `/full_cycle`,
  and `/quick` replaced "classification" and "bounded" with the new sizes.
  Skipping the questions ends brainstorming, not the workflow. `/plan` and
  `/full_cycle` report the builder check separately from the plan's review.
  `/quick` has no plan step, so a project with a written design makes it
  offer `/full_cycle` — `docs/workflows.md` already tells `/quick` to switch
  when scope grows.

- **`pdd-workspace`'s header is unchanged.** Upstream commented the
  create-only `.gitignore` at the write site and left its header alone; so
  does the port. The plan-less `adhoc` workspace is unaffected.

## diagnosing-superpowers port policy

**Decision: deferred again.** The skill did not change in this interval, and
a port still depends on four decisions that belong to the maintainer. This
section is the policy a port follows once they are made.

1. **Subject and name.** The skill diagnoses sessions of *this* pack and
   reports its involvement, so it ports as `diagnosing-herdrpowers`, keeping
   upstream's file layout (`prompts/`, `references/`, `templates/`) for
   diffable refreshes. Its issue step targets
   `transparent-pegasus/herdrpowers` with a template under
   `.github/ISSUE_TEMPLATE/`, and its workspace moves out of
   `~/.superpowers/`. *Needs the maintainer:* the name, and whether issues
   are filed here at all.
2. **A run spans many sessions.** One workflow run is the orchestrator's
   session plus a fresh session per reset-backed delegation, each in its
   own CLI's store (Claude Code, Codex, OpenCode, Cursor, Grok, agy, …).
   Upstream's `session-discovery.md` is already harness-agnostic; the port
   adds one step that maps delegations to panes to sessions from the report
   files under `<REPORT_DIRECTORY>`, the PDD ledger, and the completion
   markers, and records each mapping with its provenance in the case file.
3. **The analysts become a delegation task.** Upstream's seven parallel
   analysts, per-candidate similar-session readers, and the scrub loop are
   work, routed like any other: one work task (for example
   `session-analysis`) in `roles.yaml` plus the tables in `orchestration`,
   `commands/init.md`, and `docs/roles.md`. The scrub audit must stay a
   fresh context, so it is a review task, or part of one. Inline is the
   degraded path, run sequentially and under upstream's context-safety
   rules. *Needs the maintainer:* the task names and their shipped
   role/mode.
4. **Transcripts leaving the orchestrator need consent.** A delegated
   analyst sends session content — other panes' transcripts, file contents,
   possibly secrets — to whichever vendor its pane runs. Upstream never
   faces this, because its subagents share the session's vendor. The port
   asks before any transcript goes to a different vendor, and without that
   consent analyses inline or on a same-vendor pane. *Needs the
   maintainer:* per-run consent, a configuration key, or both.
5. **Kept verbatim:** read-only on session files, a `path:line` citation for
   every finding, intake before analysis, approval gates before any issue,
   comment, or archive, and "report involvement, never diagnose the pack".

Until those four are settled, `README.md` lists the skill as not carried yet
and links here.

-## Three Paths
-
-Before your first question, classify the request and say the classification out loud — "this looks bounded, so I'll present a short design here rather than write a spec" — so the user can override it:
-

-- **Architectural** — new projects, new subsystems, changes that restructure how components fit together or alter interfaces others depend on. Follow the full process: questions, approaches, sectioned design, written spec, then the writing-plans skill.
