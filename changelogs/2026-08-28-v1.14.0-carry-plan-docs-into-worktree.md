# v1.14.0 — Carry design/plan docs into the worktree

## Summary

`using-git-worktrees` gains Step 1c: after the isolated workspace exists (native
tool or git fallback alike), the task's design doc and implementation plan —
written before the worktree existed and therefore sitting untracked in the
primary checkout — are moved into the worktree and committed there. The primary
checkout's HEAD stays clean, and the docs ride the feature branch instead of
being stranded as untracked files.

All worktree creation routes through `using-git-worktrees`, so the single edit
covers `execute`, `quick`, `full_cycle`, `execute_parallel`,
`executing-plans`, and `pane-driven-development`. Workflows without a plan
phase (`quick`) hit the "nothing untracked" guard and skip silently.

## Details

- **Untracked (`??`) entries only.** Moving a tracked file would dirty the
  primary checkout — the opposite of the point. A doc already committed on
  `<BASE_BRANCH>` is left alone; the worktree has it via the branch.
- **Scoped to this task's docs** (the `<DESIGN_DOC_PATH_PATTERN>` /
  `<PLAN_PATH_PATTERN>` paths the invoking workflow wrote), never a sweep of
  the whole plans directory — other tasks' drafts stay put.
- **Plain `mv`, not `git mv`.** Each working tree has its own index;
  `git mv` cannot cross them. Add and commit inside the worktree.
- **Multi-worktree runs** (`execute_parallel`, `full_cycle` under
  `delegation.execution: parallel`): docs go into the coordination worktree
  only. Per-track worktrees branch off `<BASE_BRANCH>` and never see the plan;
  per-track briefs cite the coordination worktree's absolute path. Tracks never
  touch the plan file, so integration back onto the coordination branch cannot
  conflict on it.
- **Report the new absolute paths.** Later delegation briefs and review
  requests must cite the new location; the old path no longer exists.
- Step 0's already-in-worktree branch gets a one-line pointer to Step 1c for
  resumed sessions whose docs are still stranded in the primary checkout.
- Reuses the existing `<DESIGN_DOC_PATH_PATTERN>` / `<PLAN_PATH_PATTERN>` keys
  — no new `<KEY>` placeholder, no `commands/init.md` key-table change.
- Quick Reference gains three rows; Common Rationalizations gains one ("panes
  can read the plan from the main checkout anyway").

## Not changed

- No command file changed: the skill is self-contained and every caller
  already records the worktree's absolute path for briefs.
- Declined-consent and sandbox-fallback paths (work in place) skip the move —
  there is no worktree to carry into.
- `roles.yaml`, routing, and review gates untouched.
