# v1.8.0 — Generalist runs on the orchestrator; reviews in `mode: orchestrator` spawn a subagent

## Summary

The shipped `generalist` role no longer binds to an agent type: it binds to `orchestrator`, the pane the user typed into. Every task the pack ships on that role therefore moves from `mode: delegate` to `mode: orchestrator`, and a new rule covers the one case where that would have created a self-review.

`orchestrator` is not an agent type, so "a fresh idle pane of the generalist role" does not exist. Changing the role binding without changing those modes would leave four assignments unresolvable — the mode changes are part of the same change, not a separate preference.

## What changed

`skills/orchestration/roles.yaml`:

- `roles.generalist.agent`: `cursor` → `orchestrator`.
- `assignments.simple-coding.mode`, `assignments.chores.mode`, `assignments.verification.mode`: `delegate` → `orchestrator`.
- `assignments.documentation-impact-review.mode`: `delegate` → `orchestrator` (still `enabled: true`).
- `verification.description` gained the `mode: orchestrator` half of the evidence rule: a delegated run is a claim accepted on quoted output, an orchestrator run produces the output directly.
- The `mode:` comment block now splits `orchestrator` by task kind.

`fallbacks.cursor: [grok]` is unchanged — `cursor` is still one of the two `reviewer` entries.

## Reviews in `mode: orchestrator`

A **review** task resolved to `mode: orchestrator` does not run inline in the orchestrator's session. The orchestrator spawns a fresh in-process subagent and hands it the same self-contained review brief a delegated pane would receive; the subagent's fresh context is the independence property, the same one a reset pane provides. This is the pack's second documented exception to "no in-process subagents" (the first being the fresh-context sample in `writing-skills`).

Without it, `documentation-impact-review` on the orchestrator would be the orchestrator reviewing the plan it wrote in the same session — the exact case "Independence is structural" forbids.

Rules, in `skills/orchestration/SKILL.md` under "Reviews in `mode: orchestrator`":

- Never inline. No subagent available means the review degraded, and the report says so; it never means grading your own work.
- The brief is self-contained — the review reads the code, not the orchestrator's conversation.
- Work tasks are unaffected: `mode: orchestrator` on a work task is still inline execution.
- The report names a review that ran in a spawned subagent.
- A list role under `mode: orchestrator` becomes one spawned subagent per entry; the different-agent-types rule does not apply, because the type is the orchestrator's own.

## Migration

Repositories with their own `.herdrpowers/config.yaml` are unaffected — that file wins key by key, and anything it omits now falls back to the new defaults. A repo that wants the old behavior sets `roles.generalist.agent` back to an agent type and those four assignments back to `mode: delegate`.
