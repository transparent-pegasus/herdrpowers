# v1.18.0 — OpenCode 2

## Summary

OpenCode 2 requires a default plugin definition with `id` and `setup(ctx)`;
the existing named v1 function and returned `config` hook do not run there.
The OpenCode entrypoint now supports both APIs from the same package.

For v2, install with:

```bash
opencode plugin add git+https://github.com/transparent-pegasus/herdrpowers.git
```

Use `opencode2` instead if that is the v2 executable's name. OpenCode
1.18.29+ retains the previous `opencode plugin -g herdrpowers@git+https://github.com/transparent-pegasus/herdrpowers.git`
installation command.

## Changes

- The default export has the stable ID `herdrpowers`, v2 `setup`, and a v1
  `server` adapter. The named `Herdrpowers` export remains available for
  direct imports. V1's config hook also avoids duplicate skill paths when
  called repeatedly.
- V2 registers the 16 bundled skills through `ctx.skill.transform`, with
  their actual `SKILL.md` paths, decoded name/description scalars, and
  Markdown bodies. Supporting scripts and references remain relative to
  each installed skill. Existing skills with the same ID are preserved.
- V2 registers the seven `/herdrpowers:*` workflows through
  `ctx.command.transform`, preserving commands already present at setup.
  Executing a workflow submits its body and literal arguments to the same
  session, retaining attachments and queue/steer delivery. Built-in `init`
  and `review` keep their names and behavior.
- The JavaScript definition implements the public v2 contract directly;
  `Plugin.define` is an identity helper, so no SDK runtime dependency is
  needed. `package.json` keeps its `.mjs` main and does not change the module
  type of CommonJS support scripts. Its new `files` allowlist includes the
  plugin, payload, documentation, and retained `LICENSE`/`NOTICE`, excluding
  local state from npm artifacts.
- README, OpenCode setup documentation, skill/workflow docs, and maintainer
  validation instructions describe both APIs. The package and four versioned
  plugin/marketplace manifests move together to 1.18.0.

The implementation follows the official
[v2 plugin contract](https://opencode.ai/v2/docs/build/plugins), including
[the shared v1/v2 export shape](https://opencode.ai/v2/docs/build/plugins#support-v1),
and was checked against the
[v2.0.32 source](https://github.com/anomalyco/opencode/tree/v2.0.32/packages/plugin/src).
Routing defaults, role assignments, review gates, and composer key sequences
are unchanged. Upgrading a delegation target still requires its composer
probe; plugin loading alone does not verify terminal automation.

## Verification

- Six regression tests in `tests/opencode/plugin.test.mjs`, written by the
  implementing session: v1/v2 export contracts, v1 config preservation and
  idempotence, all skill registrations and metadata, command overrides,
  current-session execution with literal arguments and attachments, and
  prompt error propagation. Before implementation, the suite failed because
  the entrypoint had no default export; all six pass after the change.
- `npm pack` includes all 16 skills, all seven workflows, their supporting
  files, and `LICENSE`/`NOTICE`, with no local `.claude/` state. A temporary
  Git repository made from that archive was installed through the real v1
  and v2 plugin installers, using isolated XDG config/cache/data/state paths.
- OpenCode **2.0.32** loads the installed package through its `main` and
  reports `herdrpowers` active. Its API lists the 16 skill IDs and seven
  workflows, retains a project skill override and command override, and
  keeps built-in `init` and `review`. A temporary prompt observer verifies
  actual workflow execution preserves the session, arguments, file/skill
  attachments, and queue delivery, then stops before any model request.
  Loading the checkout's `.opencode-plugin/` directory also passes.
- OpenCode **1.18.35** loads the installed package's v1 adapter:
  `debug config` includes one bundled skill path, all seven workflow names,
  and the user's command override; `debug skill` discovers all 16 skills.
  The packed CommonJS graph helper reaches its normal usage message without
  an ESM error. Rendering was not exercised because Graphviz is absent.
- Both `claude plugin validate` commands pass with the existing root
  `CLAUDE.md` and missing-icon warnings. `bash tests/pane-model/run.sh`
  passes all 26 cases. The legacy-reference search finds only the existing
  prohibition/history explanations. The v1 entrypoint smoke check passes.
- `plugin-scanner 3.46.0` scores **95/100**, with the same two lockfile and
  five informational presentation findings documented in `.github/SCANNER.md`.
