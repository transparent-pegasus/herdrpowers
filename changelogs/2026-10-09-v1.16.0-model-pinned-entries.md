# v1.16.0 — Model-pinned role entries

## Summary

herdr reports each pane's agent type but not the model it runs, so two panes
of one CLI on different models — a cursor pane on Grok 4.7 and another on Muse
Spark 1.3 — were the same thing to routing, and a list role could not name
`cursor` twice. A role binding, a fallback key, and a substitute can now pin a
model as `agent@model` (`cursor@Muse Spark 1.3`). The pack reads the model from
the footer each CLI draws below its composer, selects only panes that show it,
and never switches a pane's model. The shipped defaults now pin models.

## Details

- **Where the model comes from.** Measured on herdr 0.9.3: `pane list`,
  `pane get`, and `agent get` carry no model field, and none of the installed
  integration hooks (claude, codex, cursor, antigravity-cli, grok) reports one.
  A CLI's config file is shared by every pane running it
  (`~/.cursor/cli-config.json`), and launch arguments and splash headers go
  stale: a grok pane kept `Model · Grok 4.6` in its header after `/model`
  switched it to Grok 4.7, and only its footer changed. The footer is the one
  per-pane source.
- **`pane-model.sh` (new).** Prints a pane's footer model line; with a model
  argument it exits `0` only when that line contains the model,
  case-insensitively. It finds the last composer line by a per-CLI anchor
  (claude `❯`, codex `›`, cursor `→`, agy `>`, grok `❯`, opencode `┃`) and
  takes the first text line below the composer's closing border or blank line,
  so a composer holding wrapped text is never read as the model line — claude
  and cursor both put an interrupted prompt back into the composer. grok's
  footer follows its composer line directly; opencode draws the model line
  inside its composer box. It fails closed: a kind with no rule exits `3`, and
  a screen with no composer line or an open model picker never matches. claude
  shows a model line only through a user `statusLine` that prints the model.
- **Entry syntax.** Split at the first `@`: the agent type on the left, the
  model on the right. A bare type matches any model. `orchestrator@…` is a
  configuration error, routed as `orchestrator` and named in the report.
- **`composer-submit.sh <pane> <instruction> [<model>]`.** With a model, the
  footer must show it before any key is sent and again after the reset, polled
  for up to `HERDR_COMPOSER_CONFIRM_TIMEOUT_SECONDS` because the reset redraws
  the screen. Otherwise it exits `5`, which — like `2` and `4` — never started
  a delegation and never counts toward exhaustion.
- **`probe-composer.sh <pane> [<model>]`.** Steps 4-5 submit through the model
  check. Step 11 (new): the model line is still readable after the probe's
  resets, and still shows the model. Step 12 (new): a submission pinned to a
  model the pane does not run is refused with exit `5`, and the pane stays
  idle. Both skip for a kind with no model-line rule.
- **List roles.** "The delegations come from different agent types" now also
  allows one type twice when both entries pin models that differ, neither
  containing the other: `cursor@Grok 4.7` and `cursor@Muse Spark 1.3` are two
  reviewers; `cursor` beside `cursor@Grok 4.7` is the same type twice.
- **Exhaustion, fallback, escalation.** A pinned entry is exhausted as written,
  so `cursor@Grok 4.7` running out leaves `cursor@Muse Spark 1.3` usable.
  Fallbacks are looked up for the entry as written, then for its bare type.
  Escalation may move to a pane already running a different model.
- **Shipped defaults.** Reviewer: `opencode@GPT-6 Astra`,
  `cursor@Gemini 4 Argon`, `cursor@Grok 4.7`, `cursor@Muse Spark 1.3` — four
  reviews per review task. Coder: `opencode@GPT-6.1 Sol`. Each entry falls
  back to the same model on another CLI, then to that CLI bare; `cursor: [grok]`
  is gone. A session without these models fails closed on each pinned entry and
  reaches the bare fallbacks. The Antigravity CLI's herdr kind is `agy`, not
  `antigravity`.
- Documentation: the orchestration and sibling-pane skills,
  `pane-driven-development`, `commands/init.md`, `docs/roles.md`, `README.md`,
  and the `CLAUDE.md` invariants and validation list. Version 1.16.0 across the
  four manifests and `package.json`.
- Authorship: every change was made inline in the orchestrator pane. An
  earlier delegated attempt was reverted at the owner's request, so the tests
  and the code share one author.

## Verification

- `bash tests/pane-model/run.sh`: 26 offline cases over real
  `herdr pane read --source visible` captures of all six CLIs, plus three
  derived screens — RED first (26 failures with the script absent), then
  26/26.
- `claude plugin validate .claude-plugin/plugin.json` and
  `claude plugin validate .`: pass, with the existing root-`CLAUDE.md` warning.
  The `rg` check finds only the existing prohibition text. The OpenCode entry
  point registers `skills/` and seven workflows. `git diff --check` is clean.

Live, herdr 0.9.3, one pane of each CLI in one tab:

- `probe-composer.sh <pane> <model>`, all six in parallel: claude
  (`Opus 5.5`), codex (`GPT-5.6-Luna`), opencode (`GPT-6.1 Sol`), cursor
  (`Muse Spark 1.3`), and agy (`Gemini 3.8 Flash`) passed 12/12 — the reset
  keeps every footer model, and a pin to another model is refused with exit
  `5` before any key is sent. These are the first probe passes for claude and
  agy. grok (`Grok 4.7`) passed steps 11-12 but failed 4-5, 8, and 9 with exit
  `3`: herdr reported the pane `idle` for 30 seconds of polling while it
  counted to 60 (detection rule `osc_title_idle`, title `grok`). The task ran;
  only the start check failed. This predates v1.16.0 and does not depend on
  the model check.
- An earlier attempt read a cursor pane's model line as `output.` — the second
  line of an interrupted prompt that cursor had restored to its composer. The
  separator rule fixes it, and the fixture `cursor-wrapped-composer.txt` is
  that screen.
- `pane-model.sh` read the right footer on all six panes, and the selection
  snippet in "Model-pinned entries" resolved the shipped defaults against the
  tab: `cursor@Muse Spark 1.3` matched the cursor pane and
  `opencode@GPT-6.1 Sol` the opencode pane; `cursor@Grok 4.7`,
  `cursor@Gemini 4 Argon`, and `opencode@GPT-6 Astra` matched nothing, while
  their fallbacks `grok@Grok 4.7`, bare `agy`, and bare `codex` each found a
  pane.

## Not verified

- No pane ran `GPT-6 Astra`, or `Gemini 4 Argon` or `Grok 4.7` on cursor, so
  those default entries were exercised only as non-matches.
- After probe step 9, claude and cursor hold the interrupted prompt in their
  composer, and cursor's `ctrl+u` clears one visual line per press. The
  helper sends a single `ctrl+u`, so a wrapped leftover can survive it; the
  sibling-pane workflow's empty-composer check is what keeps such a pane out
  of the candidates. Unchanged here.
- `shellcheck` is not installed.
