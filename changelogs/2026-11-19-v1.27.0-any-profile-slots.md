# Fill profile `any` slots from the task (v1.27.0)

A profile may write the bare literal `any` for `orchestrator` or for a role
that takes one target. The task fills it for that run: `solo Opus 5.5 max`,
or `neon-fable coder: codex`. A value is an optional kind, then optional model
and effort; omitted parts stay open, so `codex` accepts any codex model and
effort.

- **Contract**: `skills/orchestration/references/profiles.md` gains an
  "`any` slots" section and `any` in the profile key table. A bare value fills
  the only `any` slot right after the profile name; otherwise the value names
  its slot. An unfilled slot accepts every agent, and an unfilled owner keeps
  the reception pane. A slot without a kind matches any kind by footer, cannot
  be started, and has no fallback key. A value for a slot not written `any`,
  or a bare value for several slots, is an error raised before routing. Fills
  freeze with the run and appear in the handoff and the final report.
- **Presets**: `fable` (Fable 5.2 owner, `any` coder, Astra and Neon reviewers),
  `neon-fable` (Gemini 4 Neon owner, Fable 5.2 planning and decisions, `any`
  coder, the same reviewers), and `solo` (`any` owner) replace the six earlier
  presets. `fable` merges `fable-sol-ultra` and `fable-opus-ultra`
  (`fable coder: codex GPT-6.2-Sol max`), and its `agy` reviewer moves from
  `Gemini 4 Argon` (`High`) to `Gemini 4 Neon` (`XHigh`). `solo` replaces
  `sol-solo` and `opus-solo` (`solo claude Opus 5.5 max`). `sol-astra` and
  `opus-fable` are removed. A consumer that selects a removed name keeps
  working only through a local copy installed by an earlier init; without
  one, selection fails explicitly.
- **Docs and tests**: The profiles README, `README.md`, `docs/roles.md`,
  `commands/init.md`, and the orchestration skill and README describe `any`
  and drop the six-preset wording. `tests/orchestration-profiles/profiles.test.mjs`
  covers the new preset set and where `any` may appear.
  Manifests and `package.json` advance to `1.27.0`.
