# Upstream Refresh — v6.4.1 and v6.4.2: Inline Execution Rebuilt, Plans Record Decisions

Adopts the payload-relevant parts of two upstream releases. v6.4.1 rebuilt
`executing-plans` from a 64-line stub into a real inline mode (upstream calls
it Native execution), made the user review the saved plan before anything
runs, added the plan's Review Focus section, taught the final reviewer to
judge unspecified behavior by what a reasonable user expects and to list what
it declined to judge, made the project's suite define green in TDD, gave
same-basename plans separate workspaces, made `review-package` refuse empty or
non-descendant ranges, and switched skill prose to invoking bundled scripts
through their interpreter. v6.4.2 rewrote `writing-plans` so a plan records
decisions instead of transcribing the code. v6.4.0 never shipped.

Bumps the pack to **1.15.0** across all four manifests: `executing-plans`
changes from checkpointed batches to continuous execution with one final
review, and the plan format changes — new behavior, not a fix.

## Reconciliation decisions

- **Inline overrides the work routes, never the review gate.** Upstream's
  Native mode has the session do everything except the final review. Here
  that needed one explicit statement: under `executing-plans`, every task,
  test, and fix runs in the orchestrator pane whatever `complex-coding`,
  `simple-coding`, `test-authoring`, `review-fixes`, or `chores` resolve to —
  the user's choice of inline, or the absence of panes, is what makes it
  inline — while the final review still resolves from
  `assignments.final-branch-review`. A disabled gate skips it and the branch
  is reported unreviewed, as in `pane-driven-development`.

- **"Dispatch the reviewer on the most capable model" became the
  `final-branch-review` gate.** Panes have no model dial
  (`pane-driven-development`: escalation is a type swap), so the review goes
  through `requesting-code-review`, which resolves the gate's role and mode
  and submits `review-brief.md` to reset-backed panes. The plan's Review Focus
  section and a pointer to the ledger's `Ruling:` lines travel in
  `[PLAN_OR_REQUIREMENTS]`, as upstream hands them to its reviewer.

- **No reviewer available → a disclosed self-review, matching `/quick`.**
  Upstream's no-subagent-tool branch has the author perform the review and
  say so. The pack already degrades this way: `/quick` reviews its own change
  against `requesting-code-review`'s brief and states the review was not
  independent, and the plan-review gate critically reviews its own plan when
  no reviewer type is available. `executing-plans` follows that precedent —
  `Final review: self-review (no reviewer available)` in the ledger, said
  plainly in the final message, the user decides. It never applies to a
  disabled gate: a disabled review stays removed.

- **The ledger is pane-driven-development's.** Same workspace
  (`pdd-workspace`), same identity line (`# PDD ledger — plan: …`),
  compatible completion lines, so a plan can switch executors mid-flight, as
  upstream intends between its two executors. The helpers live in
  `skills/executing-plans/scripts/` and call `pane-driven-development/scripts/`.

- **Inside a workflow, the workflow keeps its own order.** Upstream has no
  workflow layer. Here `/execute`, `/full_cycle`, and the others degrade to
  `executing-plans` for the implementation step, then run documentation,
  verification, and the final review in their own order. Running the skill's
  final review at the end of the task loop would review the branch before the
  documentation update, then review it again. The skill now says: inside a
  workflow, run Setup and the Task Loop, return to the workflow, run its
  final-review step as the skill's Final Review describes, and put the
  rulings and deferred minors in the workflow's report.

- **The final report names what inline gave up.** The pack requires every
  report to name which pane wrote the tests and which independence was lost.
  `executing-plans`' Finish gains one paragraph: no per-task review, tests
  written by the implementing session, and how the final review ran — fresh
  session, self-review, or disabled.

- **`task-done`'s silent-pass bug was fixed on the way in.** As released in
  v6.4.1 and v6.4.2, `task-done` aborts under `pipefail` when a passing test
  command prints nothing: `grep -v` matches no line, the assignment fails,
  and the task is silently not recorded — exit 1, no stderr. Upstream fixed
  it on `dev` after the tag (`907ad21`, #2385). A newly ported file was not
  going to ship a known silent failure, so the one-line guard
  (`|| last="(no output)"`) came with it; a mutation run without the guard
  reproduced the bug.

- **The executing-plans helpers call the PDD scripts through bash.**
  Upstream's v6.4.x `task-start` and `task-done` still exec `task-brief` and
  `sdd-workspace` directly, while the same release made the SDD helpers call
  each other through the interpreter because a marketplace extractor strips
  exec bits (#2040). This pack ships to Codex too, so the ported helpers use
  `"${BASH:-bash}"` like the rest, and a copy with every exec bit stripped was
  exercised in Verification.

- **The interpreter rule reaches the pack's own scripts.** Upstream changed
  the prose for its own helpers; the failure class is the same for
  `composer-submit.sh` and `probe-composer.sh`, the pack's delegation
  transport — a stripped exec bit there stops every delegation on such an
  install. Every invocation in `using-herdr-sibling-panes`, the five briefs,
  `README.md`, and `docs/roles.md` now goes through `bash`, as does
  `probe-composer.sh`'s own call to the submit helper.

- **The plan-less `adhoc` workspace stays outside the marker scheme.** This
  pack's `pdd-workspace` takes `-` or no argument for plan-less flows
  (`/quick`, ad-hoc reviews) and returns the shared `adhoc` directory. That
  directory is shared by design, so it gets no ownership marker and is never
  disambiguated; markers apply to plan files only, exactly as upstream's.

- **"Declined to judge" is ruled on wherever the brief is used.** Upstream's
  only consumer of the new list is `executing-plans`. Here `review-brief.md`
  also serves `pane-driven-development`'s final review and every workflow's
  final review through `requesting-code-review`, and the brief promises the
  reviewer that each line is ruled on. Both consumers gained one instruction
  to do so, and "the executor" became "the orchestrator". The vision-document
  clause stays in the final-review brief only, where upstream placed it.

- **TDD's "project's test command" is `<FULL_TEST_SUITE_COMMAND>`.** The
  skill already resolves that key for "before committing"; the new paragraph
  names it instead of upstream's generic examples.

- **The handoff names this pack's two executors.** "Subagent-driven /
  Native" became "Pane-driven / Inline", with costs stated in sessions rather
  than subagent contexts; Pane-driven is offered only when `HERDR_ENV=1` and
  an idle in-scope pane exist. One sentence ties the handoff to the
  workflows: inside `/plan`, `/full_cycle`, and the rest, the workflow's
  review and approval steps are the handoff and its execution steps are the
  supplied method — the same rule as v6.3.0's "workflows outrank the router".

- **Phrasing follows each file.** Brainstorming and writing-plans say "the
  user", so adopted text there was converted from "your human partner".
  `executing-plans` keeps "your human partner", matching
  `pane-driven-development`, whose rulings and continuous-execution passages
  it shares nearly verbatim.

- **Self-review numbering keeps Track partition at 4.** Upstream's new
  checks become 5 (Review Focus) and 6 (Proportion); the pack-native Track
  partition check keeps its number. The Review Focus section sits after
  Global Constraints and before the pack's Tracks table — after Global
  Constraints, as upstream places it.
