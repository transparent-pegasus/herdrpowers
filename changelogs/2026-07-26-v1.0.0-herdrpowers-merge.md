# v1.0.0 — herdrpowers: superpowers-extended × herdr-orchestration

## Summary

New pack. `herdr-orchestration` merged into `superpowers-extended`, with the vendored official `herdr` skill as the third leg. Every dispatch in the development cycle now goes to a **herdr sibling agent pane** through `orchestration` → `using-herdr-sibling-panes`; the pack ships no in-process subagent dispatch and no named agent personas.

## Removed

| Removed | Why | Replaced by |
|---|---|---|
| `agents/code-reviewer.md`, `agents/test-engineer.md` | Roles bind to agent types, not personas | `skills/orchestration/roles.yaml` |
| `skills/requesting-test-creation/`, `skills/receiving-test-creation/` | The implementing pane writes its own tests | `test-driven-development`, owned by the Coder pane |
| `skills/dispatching-parallel-agents/` | In-process parallel subagents are prohibited | `/execute_parallel` track extraction + one pane per worktree |
| `docs/agents.md` | Described the removed personas | `docs/roles.md` |

## Renamed

- `skills/subagent-driven-development/` → `skills/pane-driven-development/` (rewritten for pane delegation; kept pre-flight plan review, the four-status protocol, file handoffs, reviewer-brief construction rules, and the durable progress ledger; dropped Model Selection, which does not apply to panes, in favor of role selection from `roles.yaml`)
- `implementer-prompt.md` → `implementer-brief.md`, `task-reviewer-prompt.md` → `task-reviewer-brief.md`, `requesting-code-review/code-reviewer.md` → `review-brief.md` (all restructured as one-line composer instruction + a contract written to a file, because `composer-submit.sh` rejects embedded newlines and scrollback is lossy)
- `scripts/sdd-workspace` → `scripts/pdd-workspace`; workspace path `.superpowers/sdd/` → `.herdrpowers/pdd/`
- Config section `Superpowers Extended Configuration` → `Herdrpowers Configuration`; command namespace `/superpowers-extended:` → `/herdrpowers:`

## Added

- `skills/herdr/` — the herdr project's official agent skill, vendored unmodified (Apache-2.0); its README carries a provenance header and absolute upstream link targets
- `skills/orchestration/`, `skills/using-herdr-sibling-panes/` — from herdr-orchestration, with development-cycle routing (implementation, test authoring, and code review → Coder; chores → Generalist), review-independence rules, and an extended task contract (absolute worktree path, report-to-file, verify-don't-trust)
- `docs/roles.md` — the four roles, where independence comes from, exhaustion and fallback
- Config keys `BASE_BRANCH` and `REPORT_DIRECTORY` in `commands/init.md`
- `NOTICE` — third-party attribution

## Restructured commands

- `/plan` — plan creation is followed by **independent double review** by two Reviewer agent types in separate panes; the plan is complete only after findings are resolved and the user approves. Code is not touched before that.
- **Integration is offered, not assumed.** The final step of `/execute`, `/execute_parallel`, and `/full_cycle` no longer says "merge and clean up": it presents the candidates and executes only the one the user names. `finishing-a-development-branch` grew a fifth option (**push to origin only, no PR**) alongside merge-locally / push+PR / keep / discard, and cleanup now runs for merge and discard only.
- `/execute`, `/execute_parallel`, `/full_cycle`, `/quick` — each gained an **Orchestration** section: role routing, the per-delegation contract (absolute worktree path, report file under `<REPORT_DIRECTORY>`, completion marker, no re-delegation), and honest degradation when `HERDR_ENV` is unset or no idle pane exists. Worktrees branch from `<BASE_BRANCH>`; verification runs inside the worktree; a delegated "verified" claim is checked against the report file. `/full_cycle` now runs the 7-phase default procedure and stops for the owner's integration instruction rather than merging on its own.

## Reconciliation decisions

- **Test independence.** Cutting `test-engineer` removes the structural guard against grading your own homework. The compensating control is explicit: the implementing pane's assertions must come from the requirements, the RED run is a required report artifact, and the reviewing pane now **reviews the test code** (does it assert the requirement, would it fail on regression) instead of only auditing test evidence. Both halves of that trade are documented in `test-driven-development`, `task-reviewer-brief.md`, and `requesting-code-review/review-brief.md`.
- **`executing-plans` kept** as the inline fallback for when herdr panes are unavailable, rather than deleted as a "non-pane" path.
- **`writing-skills` kept intact.** Its subagent-based pressure testing is skill authorship, not the development cycle; the one prescriptive line now names a reset pane or a raw API call as the fresh-context source and restates that the Agent tool is not used.
- **Licensing:** the pack is Apache-2.0 because `skills/herdr/` is vendored under it. MIT-licensed material from superpowers-extended, obra/superpowers, and herdr-orchestration is redistributed under Apache-2.0 with attribution in `NOTICE`.
- Upstream sync point is unchanged (`obra/superpowers` v6.1.1, `d884ae0`); this entry records a structural merge, not an upstream refresh.
