# v1.29.0 — Subagent fallback, effort `any`, and helper fixes

## Summary

herdr-orchestration v0.9.0 took this pack's orchestration changes through
`1921c31` and added work beyond them. This release brings that work back:

- **Subagent fallback.** New `delegation.subagent_fallback` (default `true`).
  A separate target that is unavailable — no live in-scope agent, none started
  under lifecycle permission, and no usable fallback substitute — runs in a
  fresh in-process subagent of the active owner's own agent kind, with the same
  self-contained brief and no re-delegation. It carries none of the target's
  kind, model, or effort, and the report names those lost constraints. One
  subagent covers all unavailable slots of one review. An explicit empty
  fallback list now rules out pane substitutes only; `false` restores the
  earlier outcome. Exhausted targets keep their fallback and
  `reviewer_usage_limit` rules, and owner selection never uses this step.
- **Effort `any`.** A target may write `effort: any`: no effort is fixed, the
  active owner picks one per delegation and reports it. `pane-model.sh` and
  `composer-submit.sh` verify only the model for `any`. `fable` and
  `neon-fable` now give generalist work to `Gemini 4 Hydrogen` at an
  owner-chosen effort, and the shipped profiles README explains it.
- **Cursor effort.** cursor-agent shows the selected model's display name:
  the base name, then one label per set parameter (context size, effort,
  `Fast`, `No Thinking`). `pane-model.sh` peels those labels off the end of
  the name — never into the requested model, ignoring ` · MAX`, statusLine
  fields, and right-aligned footer labels — and needs exactly one effort among
  them. A live pane showed `Grok 4.7 256K Extra High`. The synthetic
  `Reasoning:` fixtures, a field no CLI renders, are replaced by that capture
  and synthetic variants of it.
- **Liveness check.** `composer-submit.sh` compares the foreground process
  group instead of the first listed pid and re-reads an ambiguous reading, so
  a reset that restarts a Claude pane's helper processes no longer ends the
  submission with exit `2`. When the shell holds the terminal, it discards the
  stray line with `ctrl+c`; `ctrl+u` right after `esc` reads as one meta key in
  zsh and bash and kept the line.
- **Narrow panes.** The model/effort check before any key now follows the
  width step: opencode draws no model line at about 30 columns, so a narrow
  pane failed with exit `5` before the helper widened it. The pane-selection
  example keeps a pane that shows no footer, leaving the verdict to the
  helper.
- **Review gates hold with no reviewer left.** When no reviewer can run — no
  pane, no substitute, no subagent fallback — the gate holds and the owner's
  own review never stands in. This replaces the no-profile critical
  self-review fallbacks in `/plan`, `/quick`, the builder check, and the
  `executing-plans` final review (`Final review: held (no reviewer
  available)`).
- **Requirements in review briefs.** A review brief lists the user's
  requirements for the task verbatim, in the order given, and asks for a
  verdict on each before code findings; a later requirement wins. The review
  brief's output gains a `Requirement verdicts` section, `/plan` review
  requests and the final review pass the requirements, and the
  decision-maker brief gains a `[REQUIREMENTS]` input for instructions the
  spec does not record.
- **Orchestrator turn discipline.** The task contract says never to end a turn
  while a delegation is in flight and to keep each wait shorter than the
  calling tool's timeout; the seven brief templates now wait in 540-second
  stretches instead of one 15- or 30-minute call. Failure handling forbids
  rewriting herdr's agent state with `herdr pane report-agent` to force a
  submission.

## Skill size

`using-herdr-sibling-panes/SKILL.md` drops from 19,730 to about 15,500 bytes:
the per-CLI footer table, the composer failure modes, and the width and zoom
rationale move to `references/composer-keys.md`, each behind a read
instruction. `orchestration/SKILL.md` drops from 19,624 to about 18,700 bytes
despite the new section: the execution-strategy detail, the orchestrator-mode
review rules, and the exhaustion steps move to `references/routing.md`, which
the skill already requires before routing.

## Not taken

herdr-orchestration's standalone adaptations stay there: its config and
profile paths, its environment variable names, the removal of workflow-pack
material, and its Python test harness. The narrow-pane regression test lives
in that harness; the script change is identical here.

## Validation

`node --test` for the helpers, lifecycle gate, profiles, OpenCode, and
Antigravity suites; `tests/pane-model/run.sh`, `effort.sh`, `muse.sh`; the
skill-size check; `claude plugin validate` for the plugin and the marketplace.
Manifests and `package.json` advance to `1.29.0`.
