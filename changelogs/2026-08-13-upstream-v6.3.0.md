## Reconciliation decisions

- **"Your human partner" became "the user."** Upstream's new prose uses "your
  human partner" throughout; this pack has zero occurrences of that phrase and
  says "the user" everywhere. All adopted text was converted.

- **Workflows outrank the router.** Upstream wires brainstorming to no workflow;
  this pack invokes it inside `/plan`, `/full_cycle`, and `/quick`, whose next
  steps assume a spec and a plan exist. A bounded classification inside those
  workflows would tell the agent to skip documents the workflow's later steps
  consume. Each of the three commands gained one line: invoking the workflow is
  the user choosing its ceremony — announce the classification, never downgrade
  the workflow; a spike-shaped request is surfaced and confirmed before
  continuing. Standalone brainstorming keeps all three paths as upstream wrote
  them.

- **The bounded path's implement step names orchestration.** Upstream's
  "proceed with the normal development workflow" could read as license to
  implement inline in a pack whose entry skill routes tasks to panes. The
  bounded checklist's step 5 adds "a task the orchestration skill routed stays
  routed". One nod, in the step agents execute; the terminal-states paragraph
  stays upstream-verbatim.

- **The bounded graph branch was made faithful to its own checklist.** Upstream's
  graph enters the bounded path at "Ask clarifying questions (bounded)" while
  its bounded checklist starts with exploring project context. The node was
  renamed "Explore + clarifying questions (bounded)" rather than copying the
  mismatch or inventing new edges. "Human approves?" became "User approves?"
  per the phrasing conversion; the architectural path's existing
  "User approves design?" diamond is untouched. The updated graph renders
  cleanly (verified with `render-graphs.js`).

- **`render-graphs.js` kept CommonJS.** Upstream switched the file to ESM
  imports because its repo root `package.json` declares `"type": "module"`;
  this pack ships no `package.json`, and bare `import` in a `.js` file fails on
  Node before 22.7's default module detection. The substantive fixes were
  adopted without the module-system change: `execFileSync('dot', ['-Tsvg'])`
  replaces the shell invocation, and the availability probe runs `dot -V`
  directly instead of `which dot`, which does not exist on Windows.

- **"The controller" became "the orchestrator"** in the illegible-evidence
  clause, matching the term `task-reviewer-brief.md` already uses. The clause
  sits before Part 1 (Spec Compliance), the same position as upstream's, and
  complements the existing "do not re-run the suite" paragraph: one forbids
  re-running to confirm legible evidence, the other forbids re-running to
  regenerate illegible evidence. `re-review-brief.md` was left alone — upstream
  did not add the clause to its re-review prompt either.

- **The `Spec:` plan header lands in both halves of the contract.**
  `writing-plans` gains the template field; `pane-driven-development` gains the
  read-side instruction (spec is the authority the plan argues from, conflicts
  resolve against it, no reachable spec → provisional rulings noted in the
  ledger). This pairs with the 1.6.0 rulings adoption: a ruling's authority
  comes from the spec, so the spec must travel with the plan.
