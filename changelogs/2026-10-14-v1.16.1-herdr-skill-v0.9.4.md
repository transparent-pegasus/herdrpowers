# v1.16.1 — Vendored herdr skill refreshed to v0.9.4

## Summary

`skills/herdr/` had not moved since v1.0.0, which vendored it from herdr's
`master` at `c7b3d8a` (2026-07-25, between the v0.7.5 and v0.8.0 releases).
It now carries the skill of the v0.9.4 release, tag commit `7e26bad`.
`SKILL.md` is byte-identical to that tag's `skills/herdr/SKILL.md` and to what
the 0.9.4 binary prints with `herdr --skill`. Upstream ships the skill with
stable releases — `51b7064` ("fix: keep agent skill aligned with stable
releases") reverted an unreleased edit — so the vendored copy tracks a release
tag, not `master`.

The upstream repository moved from `ogulcancelik/herdr` to `herdrdev/herdr`,
and its default branch is `master`. Every absolute link target the vendored
README carried (`ogulcancelik/herdr/blob/main/...`,
`raw.githubusercontent.com/ogulcancelik/herdr/main/...`) returned 404. The
README is rebuilt from upstream's v0.9.4 README with the same treatment as
before — provenance header, relative targets rewritten to absolute upstream
URLs, now against `herdrdev/herdr` on `master` — and `NOTICE` and `CLAUDE.md`
name the new repository.

herdr 0.9.4 also changes two things the transport's rules leaned on, and the
v0.9.1 skill contradicts one of its claims. Those are reconciled in
`using-herdr-sibling-panes` and `pane-driven-development`; see
"Reconciliation decisions".

## Reconciliation decisions

- **Alternate-screen rows are not always lost.** The v0.9.1 skill says that
  for supported idle agents herdr "can collect application-owned history and
  restore the viewport afterward, but not every application or response can be
  recovered this way." `using-herdr-sibling-panes` ("Reports go to files") and
  `pane-driven-development` ("File Handoffs") said `pane read` can *never*
  recover those rows; both now say it cannot *always* recover them. The rule
  they justify — reports go to files — is unchanged, because the recovery is
  not guaranteed.
- **An idle agy or grok pane may still be working.** herdr 0.9.4: "Antigravity
  and Grok count as idle once they are back at their prompt, even if their own
  background tasks or subagents are still running." The transport selected
  candidates by `idle`/`done` and called an idle pane with no marker and no
  report "already failed" — which would re-delegate onto, and reset, a session
  whose work is still running. Three edits:
  - *Selection* (Workflow step 3): a pane still holding one of the
    orchestrator's delegations — no marker, no report yet — is not a candidate
    whatever its status.
  - *Failure handling*: a new **still running** state — agy or grok idle, no
    marker, no report, and `pane read` shows the work still going. Not
    finished, not failed: keep waiting in bounded stretches and do not
    re-delegate. grok 1.0.50 reading `idle` for a whole task (already recorded
    under "Verified keys") falls under the same row.
  - The bounded-stretch rule names the exception, and
    `pane-driven-development`'s "No marker, no report" lists the new state.
- **A retained identity is not a foreground agent.** herdr 0.9.4: "Suspending
  an agent with Ctrl+Z and bringing it back with `fg` keeps its name and saved
  conversation", and the skill adds that a retained identity "does not mean the
  agent is in the foreground; inspect the pane before sending input."
  `composer-submit.sh` refuses a pane whose foreground process is its own shell
  — that catches an agent that exited, not one suspended under another
  program, whose pid differs from the shell's. Step 3 now has the orchestrator
  `pane read` the pane and confirm its composer is on screen. The helper is
  unchanged: herdr reports no agent pid to compare against (`pane get` carries
  `agent_session`, not a process).
- **Not adopted, because the payload does not use it:** `agent prompt` and its
  `--wait` semantics (submission goes through `composer-submit.sh`), the
  `pane split` default (the payload never splits), `pane run` admission (the
  payload names `pane run` only for shells), and the `herdr status` skew rule
  (the payload relies on no 0.9.4 server feature).
- **`--machine` leaves the scope filter intact.** IDs are per server, and the
  tab-scoped `herdr pane list` the transport filters never returns another
  machine's panes.
- **The changelogs keep `ogulcancelik/herdr`.** They record what was true when
  they were written; only live pointers — `NOTICE`, `CLAUDE.md`, and the
  vendored README — moved.
