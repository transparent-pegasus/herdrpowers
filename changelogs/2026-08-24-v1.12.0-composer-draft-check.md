# v1.12.0 — Check the composer for an unsent draft before delegating

## Summary

Adopts `herdr-orchestration` commit `e35f6cd` ("docs(herdr-panes): check the composer for an unsent draft before delegating") into `skills/using-herdr-sibling-panes/SKILL.md`. Documentation only — no helper script, routing, or `roles.yaml` change. The two repositories' copies of this file diverge elsewhere (`<REPORT_DIRECTORY>` placeholders, the bounded-wait section), but the pane-selection list and the failure-handling table are identical, so the change lands verbatim.

**The gap.** Pane selection filtered on the `agent` field and `agent_status` only. A pane holding another orchestrator's unsent composer text satisfies every condition — `agent_status` reads `idle` while the draft sits there — so it was a valid candidate. `composer-submit.sh` clears the composer with `ctrl+u` before `/clear`, so delegating to that pane destroys the draft silently. Observed 2026-08-03: two cursor panes in one tab, one holding another session's unsent text, both passing every selection condition.

`pane_scope: tab` and the per-tab `flock` serialize submissions against each other; neither protects text that has not been submitted yet. `scripts/probe-composer.sh` does check that leftover composer text clears without killing the TUI, but that is a once-per-agent-type onboarding probe, not a per-delegation check, and the existing `pane read` instruction applies only to the hand-send path where the helper is unavailable.

**The change.** A new step 4 in the pane-selection list (renumbering the rest): when more than one candidate remains, read the composer with `herdr pane read "$PANE" --source visible` before sending, and drop any pane showing unsent text. An empty composer reads as an empty follow-up placeholder (`› `, `→ Add a follow-up`). With a single candidate holding leftover text, do not send — report the pane to the user. The helper cannot distinguish a half-written brief from any other composer content and must not try, so this stays an orchestrator-side check. A `someone else's draft` row joins the "Failure handling" table.
