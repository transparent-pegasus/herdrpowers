# v2.0.0 — Single-tree root layout, template/ retired

## Summary

The pack is now distributed plugin-first from the repository root. The `template/` wrapper, the mirrored `.agents/` / `.claude/` payload trees, the duplicated `workflows/` vs `.claude/commands/` sets, and the `.superpowers-extended/` support directory are gone. One tree serves every platform through the Claude Code, Codex, and Cursor plugin conventions, which all default to the same `skills/` / `commands/` / `agents/` layout.

## Path mapping (old → new)

| Old (1.x) | New (2.0) |
|---|---|
| `template/.claude/skills/` and `template/.agents/skills/` | `skills/` (single tree, bare skill-name references) |
| `template/workflows/` and `template/.claude/commands/` | `commands/` (merged: keeps the Deliverable Saves / Workflow File Edits sections) |
| `template/.claude/agents/` and `template/.agents/agents/` | `agents/` |
| `template/.superpowers-extended/docs/` | `docs/` |
| `template/.superpowers-extended/entrypoints/` | folded into `docs/instruction_snippet.md` |

## Reconciliation decisions

- Skill wording unified to the `.claude` flavor: bare skill names (`writing-plans`), `Agent tool`. The two trees' only differences were this documented drift, verified file-by-file before the merge.
- Workflow commands unified to the `workflows/` flavor (richer: keeps the shared guard sections), with init references updated to `commands/init.md` / `/superpowers-extended:init`.
- Plugin manifests slimmed: Claude Code and Cursor rely on default-directory discovery; Codex declares `./skills/` and `./commands/` explicitly.
- Checked-in consumers upgrade by re-copying `skills/`, `commands/`, `agents/` (see README "Updating an existing installation" for the pre-2.0 path mapping).

## Upstream tracking

Unchanged: still synced to obra/superpowers v6.1.1 (`d884ae0`). Future upstream refreshes now apply to a single tree with no path translation beyond `skills|commands|agents/` roots.
