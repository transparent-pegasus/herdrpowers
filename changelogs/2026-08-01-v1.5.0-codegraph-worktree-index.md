# v1.5.0 — Per-worktree CodeGraph index

## Summary

`using-git-worktrees` Step 2 (Project Setup) now runs `codegraph init` in a
newly created worktree when a codegraph plugin/tool is available and the main
checkout has a `.codegraph/` index. The index is machine-local and gitignored,
so `git worktree add` never copies it — every codegraph-aware skill
(`brainstorming`, `writing-plans`, `executing-plans`, `systematic-debugging`,
`receiving-code-review`, the pane-driven-development briefs) silently degraded
to plain search inside a worktree.

All worktree creation routes through `using-git-worktrees`, so the single edit
covers `execute`, `quick`, `full_cycle`, `execute_parallel`, and
`pane-driven-development`.

## Details

- The gate is the main checkout, not the worktree. `.codegraph/` is covered by
  the root `.gitignore` and no file inside it is tracked (`.codegraph/.gitignore`
  included), so an in-worktree `[ -d .codegraph ]` check is always false and
  would never fire.
- Not indexed in the main checkout means skip. Indexing stays the user's
  decision; the skill does not opt a repo in.
- `codegraph init` with no flags. `-i`/`--index` is deprecated upstream —
  indexing runs by default.
- Reuses the pack's existing "if a codegraph plugin/tool is available" optional
  gate. No new `<KEY>` placeholder, no `commands/init.md` key-table change, no
  detection script.
- Quick Reference gains two rows, matching the existing
  "No package.json/Cargo.toml → skip dependency install" shape.

## Not changed

- `pane-driven-development`'s throwaway detached test worktrees
  (`git worktree add --detach <plan-workspace>/tests-task-N BASE`) stay
  un-indexed. They exist for one commit and are removed immediately.
- No `roles.yaml` defaults, role, delegation-task, mode, or script changes.
