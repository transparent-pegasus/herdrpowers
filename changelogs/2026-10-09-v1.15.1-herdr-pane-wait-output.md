# v1.15.1 — Wait with `herdr pane wait-output`

## Summary

The pack waited for completion markers with `herdr wait output` and for agent
status with `herdr wait agent-status`. herdr 0.9.3 has neither: the commands
are `herdr pane wait-output` and `herdr agent wait`. The stale forms are CLI
syntax errors that exit `2` at once, and the transport skill read a non-zero
wait as a timeout — so every documented wait returned immediately, and
`probe-composer.sh` failed step 7 ("completion marker never appeared within
120s") for every agent CLI without waiting at all. The vendored
`skills/herdr/SKILL.md` has documented `pane wait-output` since v1.0.0; the
pack's own prose kept the older spelling it inherited from herdr-orchestration.

## Details

- **13 call sites.** Twelve `herdr wait output` → `herdr pane wait-output`
  (the transport skill and its README, the five brief templates,
  `docs/roles.md`, the `requesting-code-review` example, and probe step 7) and
  one `herdr wait agent-status "$PANE" --status idle` →
  `herdr agent wait "$PANE" --until idle`.
- **The semantics changed with the name.** `pane wait-output` searches the
  snapshot as it already stands, then polls; the old prose said the wait "only
  scans output emitted after it starts". Three passages were rewritten: the
  marker rules (the prompt echo is in the snapshot the wait searches first),
  long-delegation polling (a timeout can mean the marker was printed on the
  alternate screen and redrawn away), and bounded stretches (a marker printed
  between stretches can be gone before the next stretch looks — the report file
  stays the proof).
- **Exit codes are spelled out.** `1` is a timeout or a server error (JSON on
  stderr, such as an unknown pane); `2` is a syntax error and never a timeout —
  the exact misreading behind this bug.
- **Soft wraps need no flag.** The default source of `pane wait-output`
  matches a marker split by a soft wrap, so the existing marker rule holds as
  written. `pane read --source recent`, by contrast, prints soft-wrapped rows
  split — so the probe's `screen()`, which step 6 greps to predict whether the
  wait would fire on the prompt echo, now reads `recent-unwrapped`.
- **Every other herdr subcommand the payload uses** (`pane list`, `get`,
  `read`, `send-text`, `send-keys`, `zoom`, `layout`, `process-info`, `run`)
  was checked against `herdr <command> --help` on 0.9.3; all valid as written.
- The transport skill's composer-verification line records the new probe run.
- Version 1.15.1 across the four manifests and `package.json`.

## Verification

On herdr 0.9.3, in the orchestrator's own tab:

- `pane wait-output`: a marker already on screen returns `0` at once; an
  absent one — assembled at runtime, so the command's own echo cannot contain
  it — returns `1` after the timeout; an unknown pane returns `1` with
  `pane_not_found`. The old `herdr wait output` returns `2` at once.
- `agent wait <pane> --until idle|working`: `0` on a match, `1` on timeout or
  on a pane with no agent.
- Live wrap test in a narrow shell pane: a marker straddling a soft wrap is
  matched by the default source and by `recent-unwrapped`, not by `visible`;
  a marker split by a real newline is matched by none.
- `probe-composer.sh` against codex 0.162.0: all 9 checks pass. `main`'s probe
  against the same pane: step 7 FAIL, in a run that took 23 seconds in total —
  its "within 120s" wait never waited.

## Not changed

- The brief templates keep their timeout values; the skill's bounded-stretch
  rule already governs how long one wait call runs.
- `skills/herdr/SKILL.md` stays upstream's unmodified file.
